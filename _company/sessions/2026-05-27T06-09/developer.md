# 💻 코다리 — 개발자로서 팀워크 향상의 가치를 이해하고, 코드 리뷰 및 협업 과정에서의 효과적인 의사소통 방식을 개선하는 프로세스를 개발해주세요.

## 🚀 [개발팀] 협업 효율 극대화를 위한 'Code Review & Communication Protocol' 제안

**수신:** CEO 및 전사 팀원
**발신:** 개발팀 (Developer)
**주제:** 코드 리뷰 프로세스 정립 및 개발-비개발 직군 간 협업 커뮤니케 션 가이드라인

---

### 1. 🎯 배경 및 목적
현재 우리 팀은 각자의 전문성을 바탕으로 빠르게 성장하고 있으나, 개발 프로세스(코드 리뷰)와 타 직군(기획, 마케팅, 운영) 간의 **'정보 격차'**로 인해 커뮤니케이션 비용이 발생하고 있습니다. 
본 제안은 **"코드 리뷰를 단순한 코드 검사가 아닌, 지식 공유와 팀워크 강화의 도구로 정의"**하고, 개발팀의 기술적 품질과 전사적 비즈니스 목표를 일치시키는 데 목적이 있습니다.

---

### 2. 🛠️ 핵심 프로세스: "Context-Driven Code Review"

단순히 `LGTM(Looks Good To Me)`을 넘어, 리뷰 과정에 **'비즈니스 맥락'**을 포함합니다.

#### **Step 1: Pull Request (PR) 작성 표준화**
개발자가 코드를 제출할 때, 기술적 내용 외에 다음 항목을 반드시 포함합니다.
*   **[Why]** 이 변경사항이 왜 필요한가? (연관된 Jira 티켓 또는 기획 문서 링크)
*   **[What]** 무엇이 바뀌었는 *가? (기술적 변경점 요약)
*   **[Impact]** 이 변경이 사용자 경험(UX)이나 기존 기능에 어떤 영향을 주는가? (예: "결제 로딩 속도가 0.5초 개선됨", "기존 결제 버튼 위치 변경")
*   **[Testing]** 어떻게 검증했는가? (테스트 케이스, 스크린샷, 영상 첨부)

#### **Step 2: 리뷰어(Reviewer)의 역할 분담**
*   **Technical Review (개발자):** 코드 효율성, 보안, 확장성, 유지보수성 검토.
*   **Context Review (기획/운영):** PR의 'Why'와 'Impact'를 보고, 원래 기획 의도와 일치하는지, 운영상 리스크는 없는지 검토.

---

### 3. 💬 직군 간 커뮤니케이션 가이드라인 (Communication Protocol)

#### **✅ [DO] 권장 사항**
*   **비동기 커뮤니케이션 활용:** 슬랙(Slack)이나 GitHub Issue를 활용하여 상대방의 집중 시간을 방해하지 않도록 합니다.
*   **객관적 근거 제시:** "이 코드는 별로예요" 대신 **"이 방식은 메모리 사용량이 늘어날 수 있어, A 방식 대신 B 방식을 제안합니다"**와 같이 근거를 명시합니다.
*   **P-Level (Priority) 태그 사용:** 리뷰의 중요도를 표시하여 우선순위를 결정합니다.
    *   `P1`: 즉시 수정 필요 (Blocker)
    *   `P2`: 수정 권장 (Suggestion)
    *   `P3`: 단순 의견/질문 (Nitpick/Question)

#### **❌ [DON'T] 지양 사항**
*   **감정적 표현:** "왜 이렇게 하셨나요?"와 같은 공격적인 질문 대신 **"이 로직을 선택하신 배경이 궁금합니다"**라는 질문형을 사용합니다 `(Questioning over Judging)`.
*   **모호한 피드백:** "확인 부탁드립니다" 대신 **"결제 오류 케이스에 대한 예외 처리가 포함되었는지 확인 부탁드립니다"**와 같이 구체적으로 요청합니다.

---

### 4. 📈 기대 효과 (Expected Outcomes)

1.  **코드 품질 향상:** 기술적 결함 사전 방지 및 기술 부채 감소.
2.  **지식 파편화 방지:** 리뷰 과정을 통해 팀 전체의 도메인 지식(Business Logic) 상향 평준화.
3.  **신뢰 기반의 협업 문화:** 명확한 근거와 존중을 바탕으로 한 피드백 문화 정착을 통해 개발-비개발 직군 간의 심리적 안전감(Psychological Safety) 구축.

---

**"우리의 코드는 단순한 텍스트가 아니라, 회사의 비즈니스 가치를 구현하는 설계도입니다."**

위 제안 사항에 대해 의견이 있으시면 언제든 GitHub Issue 또는 슬랙 채널을 통해 공유 부탁드립니다.
