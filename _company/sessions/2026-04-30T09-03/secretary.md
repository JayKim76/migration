- 모든 Pull Request(PR) 및 작업 완료(DoD) 기준에는 관련 문서(README, API Spec, Maintenance Guide 등)의 업데이트 여부가 포함되어야 한다.

### 2. [신규 개발 SOP: 표준 운영 절차]
모든 에이전트 및 개발 작업에 적용될 새로운 표준 절차입니다.

# 🛠️ 개발 표준 운영 절차 (SOP) - [문서화 통합형]

**1. 목적**
코드의 로직과 문서의 최신성을 일치시켜, 개발 완료 후 즉시 유지보수가 가능한 상태(Maintainable State)를 유지한다.

**2. 적용 범위**
- 모든 신규 기능 개발
- 기존 코드의 버그 수정 및 리팩토링
- 인프라 구성 변경 (Terraform, Docker, CI/CD 등)

**3. 표준 개발 프로세스 (4-Step)**

| 단계 | 작업 명칭 | 상세 내용 | 산출물 |
| :--- | :--- | :--- | :--- |
| **Step 1** | **설계 및 초안** | 기능 요구사항을 분석하고, 변경될 구조를 마크다운으로 먼저 정의 | `design.md` 또는 `spec.md` |
| **Step 2** | **코드 구현** | 정의된 설계에 따라 실제 코드를 작성 (Python, SQL 등) | `*.py`, `*.sql` 등 소스 코드 |
| **Step 3** | **문서 동기화** | 코드 변경 사항을 반영하여 기존 문서(README, Guide)를 즉시 업데이트 | `README.md`, `maintenance_guide.md` |
| **Step 4** | **검증 (DoD)** | 코드가 동작하는지 확인하고, 문서가 최신 상태인지 최종 체크 | `Test Report` & `Updated Docs` |

**4. 완료 정의 (Definition of Done, DoD)**
작업이 '완료'로 간정되려면 다음 조건을 모두 충족해야 한다.
- [ ] 코드가 테스트를 통과하였는가?
- [ ] 관련 마크다운 문서가 코드의 변경 사항을 반영하여 업데이트되었는가?
- [ ] (필요 시) 새로운 API나 기능에 대한 사용 가이드가 추가되었는가?
